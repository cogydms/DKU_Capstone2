# 관리자 페이지 운영

관리자로 지정된 Google 계정은 **설정 → 관리자 전용 페이지**에서 다음 기능을 사용합니다.

- 첫 화면: **이용 계정 · 문서 관리 · 공지 관리** 세 메뉴만 표시합니다. 통계를 조회하는 대시보드 호출도 사용하지 않습니다.
- 이용 계정: 전체/회원/게스트 필터, 검색, 이름·이메일·소속·사용 상태·문서 수 조회, 계정별 문서 목록 이동, 사용 중지·재활성화.
- 문서 관리: 전체/확인 필요/분석 실패 필터, 제목·소유자 검색, 문서 삭제. 확인 필요 문서에서는 검토 내용으로, 실패 문서에서는 저장 원문 재분석으로 연결합니다.
- 문서 검토: 추출값·검증 점수·확인이 필요한 이유·원문 근거를 보여줍니다. 확인 필요/전체 항목 전환과 원문 페이지 이동을 지원합니다. 관리자 열람용이며 추출값 수정은 사용자 화면에서 진행합니다.
- 공지 관리: 작성·임시 저장·게시·수정·게시 내리기. 게시한 공지는 로그인한 사용자의 **설정 → 앱 정보 → 공지사항**에 표시합니다.

## 화면을 간소화한 범위

계정 추가·이름/소속 수정·계정 영구 삭제, 관리자 문서 추가, 통계 카드 6개, 작업 기록 페이지, 전체 검사 내역 펼치기를 제거했습니다. 관련 기존 서버 API는 호환성을 위해 유지하며, 모든 관리자 권한 검사와 감사 기록 저장은 계속 적용합니다.

## 남긴 변경 기능

- 관리자 본인과 다른 관리자 계정은 사용 중지할 수 없습니다. 사용 중지·재활성화 시 이전 로그인 세션을 철회합니다.
- 문서 삭제는 원본·분석 결과·준비 계획·연결된 할 일을 함께 삭제합니다. 외부 Google 캘린더로 내보낸 일정은 포함하지 않습니다.
- 문서 삭제에는 ‘삭제’ 입력과 관리자 Google 재확인이 필요합니다. 사용 중지·재활성화도 재확인하며, 서버에서 최근 인증을 검사합니다.
- 분석 실패 재처리는 현재 실패 상태이고 분석 결과가 없는 문서만 대상으로 합니다.

## 계정을 나중에 지정하기

1. 사용할 Google 계정으로 앱에 로그인하고 소속 등록을 완료합니다.
2. 신뢰할 수 있는 서버 환경에서 기존 Firebase Admin 자격 증명을 설정합니다. 자격 증명 파일을 앱·웹 코드나 Git에 포함하지 않습니다.
3. `backend` 폴더에서 아래 명령을 실행합니다. 이메일은 실제 지정할 계정으로 바꿉니다.

```bash
cd backend
.venv/bin/python -m app.cli.admin_role --email admin@example.com --grant
```

기본 실행은 대상 UID와 작업을 출력하는 미리보기입니다. 대상이 맞으면 다음과 같이 적용합니다.

```bash
.venv/bin/python -m app.cli.admin_role --email admin@example.com --grant --apply
```

이후 앱에서 설정에 다시 들어갑니다. 설정 진입 시 토큰을 갱신하고 서버에서 관리자 권한을 확인합니다. 표시가 갱신되지 않으면 재로그인합니다. 여러 관리자를 지정할 때는 각 팀원의 계정에 별도로 실행합니다.

권한 회수:

```bash
.venv/bin/python -m app.cli.admin_role --email admin@example.com --revoke --apply
```

권한 변경 시 다른 custom claim은 보존합니다. 회수 시 refresh token도 철회하며, 관리자 API는 매 요청마다 현재 Firebase 권한도 재확인합니다. 일반 회원·게스트는 관리자 API에 접근할 수 없고, 화면이나 프로필의 값을 바꿔도 관리자 권한을 얻을 수 없습니다.

## 저장과 범위

- Firestore 운영 환경에서는 `adminAnnouncements`에 공지, `adminAudit`에 작업 기록을 저장합니다. 현재 Firestore 규칙의 기본 차단 정책을 유지하며, 모든 읽기·쓰기는 권한을 검사하는 백엔드를 통합니다.
- `memory` 저장소에서는 공지·기록도 메모리에 저장되어 서버를 재시작하면 초기화됩니다.
- 기존 통계 API는 현재 `users/{uid}/documents`의 문서 메타데이터를 전체 조회해 집계합니다. 삭제된 문서는 집계하지 않으며 누적 분석 요청 횟수를 의미하지 않습니다. 이용 계정 수는 Firebase Auth 전체 계정 수가 아닌 프로필 등록 계정 수입니다.
- 계정·문서 목록도 모든 요청에 관리자 권한이 필요하며, 조회 작업은 감사 기록에 남깁니다. 인증 계정이 없어진 프로필은 `인증 연결 없음`으로 구분하고 자동 삭제하지 않습니다. 게스트 프로필은 실제 사람 한 명이 여러 번 생성할 수 있으므로 이용 계정 수는 실사용자 수를 의미하지 않습니다.
- 관리 API는 Firebase Auth에서 이메일·표시 이름·제공자·계정 상태·생성/로그인 시각만 선택해 응답하며 비밀번호 해시나 토큰은 반환하지 않습니다.
- 일반 관리자 목록에는 원문·추출 필드·준비 계획 내용을 반환하지 않습니다. 별도로 연 검토 페이지에는 그 문서의 추출 필드와 검증 기록을 반환하고, 원문은 요청한 한 페이지만 제공합니다. 기존 수집 단계에서 마스킹한 저장 텍스트를 사용하며 PDF·사진도 추출 텍스트로 표시합니다. 모든 검토/원문 요청에 서버 관리자 권한을 확인하고 조회 기록을 남깁니다. 원문 위치 강조는 분석 결과의 변경 시각을 비교해 이전 결과와 새로운 원문을 섞어 보여주지 않습니다.
- 재분석은 현재 실패 상태이고 분석 결과가 없는 문서에만 허용하며 기존 분석 파이프라인을 사용합니다. 관리자 열람·변경은 원래 소유자 계정의 변경·탈퇴와 같은 잠금으로 직렬화합니다.
- 공지는 revision을 비교해 동시 수정 시 409 응답으로 덮어쓰기를 방지합니다.
- 관리자 페이지는 전체 문서 메타데이터를 조회하므로 사용량이 커지면 별도 통계 집계·검색 저장소로 전환하는 것이 적절합니다.

계정이 지정되기 전에는 관리자 메뉴가 표시되지 않습니다. 개발 중 일반 계정에 임시로 관리자 권한을 자동 부여하는 우회 기능은 포함하지 않습니다.
